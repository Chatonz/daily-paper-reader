## 摘要
视觉-语言-动作（VLA）模型通常采用以LLM为中心的V→L→A通路，即先将视觉观测投影到大语言模型的表示空间，再解码为机器人动作。尽管这种设计有效，但每次策略调用都会产生大量的计算和内存开销。本文提出TurboVLA，一种新的VLA范式，将传统的V→L→A通路重构为直接的V+L→A映射。TurboVLA不再使用大语言模型作为感知与动作之间的中央接口，而是独立编码视觉观测和语言指令，通过轻量级的双向视觉-语言交互直接在两者之间交换信息，并使用紧凑的解码器预测连续动作块。这种简单设计直接从视觉和语言特征构建任务条件化表示，显著降低了VLA推理的计算和内存成本。在LIBERO上，TurboVLA仅用0.2B参数，在消费级RTX 4090上推理延迟为31.2毫秒、推理显存为0.9 GB，平均成功率达97.7%，匹配甚至超越规模大得多的VLA策略。这些结果表明，TurboVLA是当前以LLM为中心的VLA范式的简单有效替代方案，为如何连接视觉、语言和动作以实现高效机器人操作提供了新视角。代码开源在https://github.com/H-EmbodVis/TurboVLA。

## Abstract
Vision-language-action (VLA) models commonly adopt an LLM-centric $V \to L \to A$ pathway, where visual observations are projected into the representation space of a large language model before being decoded into robot actions. Although effective, this design incurs substantial computation and memory overhead at every policy invocation. In this work, we introduce TurboVLA, a new VLA paradigm that reformulates the conventional $V \to L \to A$ pathway as a direct $V + L \to A$ mapping. Instead of using a large language model as the central interface between perception and action, TurboVLA independently encodes visual observations and language instructions, directly exchanges information between them through lightweight bidirectional vision-language interaction, and predicts continuous action chunks with a compact decoder. This simple design constructs task-conditioned representations directly from visual and linguistic features, significantly reducing the computational and memory costs of VLA inference. On LIBERO, TurboVLA achieves 97.7% average success with only 0.2B parameters, 31.2 ms inference latency, and 0.9 GB inference VRAM on a consumer-grade RTX 4090, matching or outperforming substantially larger VLA policies. These results establish TurboVLA as a simple and effective alternative to the prevailing LLM-centric VLA paradigm, offering a new perspective on how vision, language, and action can be connected for efficient robotic manipulation. Code is available at https://github.com/H-EmbodVis/TurboVLA.

## 一、核心问题与整体含义（研究动机和背景）
- **现有问题**：主流VLA模型采用以LLM为中心的 **V→L→A** 通路（视觉→语言模型→动作），每一次策略调用都需要经过拥有数十亿参数的大语言模型处理，导致推理延迟高、显存占用大，难以在资源受限的机器人平台上实现实时控制（常见推理延迟在 84–202 ms，显存占用 5–16 GB）。
- **核心洞察**：执行级操控（execution-level manipulation）不需要大语言模型进行开放式的语言生成或任务分解，只需要根据指令确定当前视觉内容如何引导动作。一个轻量文本编码器（如BERT）足以提供任务相关语义，而紧凑的双向跨模态交互可以代替LLM作为感知与动作的中介。
- **整体含义**：TurboVLA提出了新的 **V+L→A** 范式，将大语言模型从执行控制通路中移除，直接通过视觉和语言的轻量交互构建面向控制的表示，大幅降低计算和内存开销，同时保持甚至提升操控性能，为实时机器人操控提供了更高效、低成本的新方案。

## 二、方法论：核心思想、关键技术细节
### 核心思想
- 直接并独立编码视觉观测和语言指令，通过轻量双向视觉-语言交互模块融合信息，再用紧凑解码器一次性预测连续动作块（action chunk），无需LLM作为中央接口。

### 关键技术细节
1. **多模态特征编码**
   - **视觉编码**：采用 DINOv3 ViT-B（单臂）或 ViT-L（双臂），提取多视角图像特征，添加位置嵌入和视角嵌入。
   - **指令编码**：采用轻量 BERT（也可用 T5-small 或 SigLIP），输出 token 级指令特征（而非池化向量），保留对象、属性和空间关系。
   - **机器人状态编码**：通过轻量投影网络单独编码当前关节/末端状态，直接送入动作解码器，不参与视觉-语言交互，使交互聚焦于任务条件化场景理解。

2. **视觉-语言交互模块**
   - 灵感来自 Grounding DINO，使用 **N=6层** 双向交叉注意力（bidirectional cross-attention）：视觉特征作为 Query 查询指令特征（instruction-to-visual attention），同时指令特征作为 Query 查询视觉特征（visual-to-instruction attention）。
   - 每层包含 LayerNorm、双向交叉注意力、前馈网络和残差连接。最终拼接两个特征流得到动作就绪特征（action-ready features）。

3. **连续动作块解码器**
   - 基于 ACT 的轻量 Transformer 解码器，输入融合后的多模态特征和机器人状态，使用 **H=12** 个可学习的动作查询（action queries）并行解码 H 步连续动作（6-DoF位置+1夹爪，共7维；双臂为14维关节位置）。
   - 无需动作分词或自回归生成，一次性输出完整动作块。

4. **训练目标**
   - 使用行为克隆（behavior cloning），损失函数为 **ℓ1 loss**，无需辅助语言建模目标。

### 公式化流程（文字说明）
- 文本编码：$Z_l = Proj(\text{BERT}(x))$
- 图像编码：$Z_v = Proj(\text{DINOv3}(I)) + \text{position\_embed} + \text{view\_embed}$
- 状态编码：$Z_s = \text{MLP}(s)$
- 双向交互：$V^l, L^l = \text{BiCrossAttn}(V^{l-1}, L^{l-1})$，6层后拼接得 $Z_{vl}$
- 动作预测：$\hat{A} = \text{Decoder}(Q_a; [Z_{vl}; Z_s])$，直接输出 $H$ 步动作块

## 六、主要结论与发现
1. **性能-效率折中领先**：TurboVLA 在 LIBERO 上以 0.2B 参数、31.2 ms 延迟、0.9 GB VRAM 达到 97.7% 平均成功率，匹配或超越参数多 10–40 倍的模型（如 π0.5 3.4B、CogVLA 8.3B）。
2. **无需 LLM 中心的执行通路**：通过轻量指令编码 + 双向视觉-语言交互，即可实现高精度实时操控，证明 LLM 并非执行级控制的必要条件。
3. **架构效率转化为实际部署优势**：在真实 AgileX Piper 平台上，TurboVLA 平均成功率 87.5%，优于 π0.5 的 76.9%，且低延迟、低显存更适合边缘设备部署。
4. **双臂任务同样有效**：在 RoboTwin 2.0 上，TurboVLA 以 0.4B 参数、43.4 ms 延迟取得 60.2% 平均成功率，超过 π0.5（57.0%）和 StarVLA-α（50.3%）。
5. **消融结果支持设计合理**：双向交互优于单向或无交互；BERT 指令编码优于 SigLIP；最佳交互深度 N=6，最佳动作视界 H=12。

## 七、优点
1. **范式创新**：提出 V+L→A 直接映射，抛弃 LLM 中心设计，显著降低计算和内存成本，思路简洁且有效。
2. **高效实时**：在消费级 GPU（RTX 4090）上实现 32 Hz 策略更新（31.2 ms 延迟），显存仅 0.9 GB，适合边缘部署。
3. **轻量但性能强**：0.2B–0.4B 参数达到甚至超越数亿参数模型的表现，降低硬件门槛。
4. **消融实验系统全面**：覆盖语言必要性、编码器选择、交互方式、深度、视界等关键因素，设计选择理由充分。
5. **跨场景验证**：单臂仿真（LIBERO）、双臂仿真（RoboTwin 2.0）、真实世界平台均取得显著效果，泛化性良好。
6. **代码开源**：便于复现和后续研究。

## 八、不足与局限
1. **高层语义理解能力有限**：TurboVLA 设计针对具体执行级指令（如“堆叠三个碗”），缺乏大语言模型的高层规划和开放式推理能力，难以直接处理复杂任务分解。
2. **实验覆盖范围有限**：仅在 LIBERO（40 个桌面任务）和 RoboTwin 2.0（50 个双臂任务）上评估，未见更复杂、多样化场景（如长时域任务、动态环境、移动操控）的验证。
3. **真实世界测试规模小**：仅在一个平台（AgileX Piper）和一个设置下测试，缺少不同机器人形态、不同传感器、不同光照/干扰条件下的鲁棒性评估。
4. **潜在偏差风险**：训练数据均来源于公开数据集或实验室采集，真实世界测试仅 4 个任务、各 40 次试验，可能存在环境/物体偏好偏差；指令相对简单，未评估复杂自然语言指令（如带修饰语、多步骤指令）的鲁棒性。
5. **泛化性未充分论证**：与需要额外嵌入式预训练（Emb. PT.）的方法（如 π0.5 在大量机器人数据上预训练）相比，TurboVLA 无额外预训练仍取得高成功率，但未测试零样本迁移或跨平台泛化能力。
6. **资源信息不完整**：未报告训练总耗时，也未提供推理延迟的详细测量条件（是否使用 TensorRT、精度等），复现时需要自行摸索。
7. **动作预测方式局限**：使用 ACT 风格的 Transformer 解码器并行预测固定长度动作块，可能在需要动态调整步长或长时间精细操控的场景下受限。
